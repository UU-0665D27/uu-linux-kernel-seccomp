# AGENTS.md — uu-linux-kernel-seccomp

Крейс «двухслойного» seccomp-BPF: низкий уровень (`src/libc`, как в C, сырые числа и libc),
надстройка (`src/rust` — `ACTION`, `Policy`), плюс дизассемблер `dump` и модуль `ptrace`
(только для чтения фильтров под отладкой). Единственная зависимость — `libc = "0.2"`:
никаких libseccomp-биндингов и высокоуровневых обёрток не заводить.

## Команды

```sh
cargo clippy --all-targets   # основной «гейт» — см. lints ниже
cargo fmt && cargo test      # fmt перед коммитом; тесты без внешних сервисов
cargo test --test api        # один набор: api | dump | fork_behavior | ptrace_read
```

## Жёсткие конвенции

- `Cargo.toml`: `[lints.clippy] all/pedantic/nursery/perf = "deny"` — действует **и на тесты,
  и на examples**. Падение на педантичном cast/collapsible_if и т.п. ломает любую сборку.
- Код, комментарии и доки — **на русском**. Это осознанный стиль репозитория, не опечатка.
- Коммиты подписаны GPG (`commit.gpgsign=true`); правки не коммитить без явной просьбы.
- Ничего сверх запроса не придумывать: пользователь явно отказывался от лишних API
  (например, верхнеуровневую `apply()`), каждый добавленный элемент проговаривать.

## Тесты — неочевидные детали

- `tests/fork_behavior.rs` — фильтр ставится в `fork`-потомке. После `fork` в потомке
  нельзя аллоцировать/panic/I/O (гонки тест-раннера): программа собирается в родителе
  заранее, результаты — через код выхода/`waitpid`. `libc::syscall` превращает сырое
  `-errno` в `-1` + `errno` — проверять errno, а не знак возврата.
- seccomp в потомке работает **без CAP_SYS_ADMIN** (unprivileged + `no_new_privs`),
  поэтому поведенческие тесты на ядро можно запускать в песочнице.
- `tests/ptrace_read.rs` требует `CAP_SYS_ADMIN`; без прав он корректно скипается
  (`ptrace::readable_by_us()`) — это норма, а не поломка. Yama `ptrace_scope=1`
  позволяет читать фильтры только у потомков.

## Особенности генератора BPF (`src/libc/bpf.rs`)

- Каждое правило начинается с `LD [nr]`: аккумулятор после правила с проверкой
  аргументов забит словом аргумента, и без перезагрузки следующий `JEQ nr` сравнивал бы
  мусор (это ловили тестами).
- Аргументы сравниваются как u64 в little-endian половинах: `arg[i]` — слова по
  `SECCOMP_DATA_ARGS_OFFSET + 8*i` и `+4`. Сравнения беззнаковые (`arg == -1` — это
  `Cmp::Eq(u64::MAX)`).
- `jt/jf` — 8 бит: цепочка проверок правила ограничена `RULE_CHAIN_LIMIT` (254),
  всей программы — `BPF_MAXINSNS` (4096, ≈1364 правила). Ошибки: `RuleTooLong`,
  `ProgramTooLong`, `ArgIndexOutOfRange`.
- Раскладка программы проверена тестом «золотого» листинга (`tests/dump.rs`) — любое
  изменение генератора ломает и dump-тест: золотой вывод править вместе с раскладкой.

## Границы API

- Номер по имени — только `resolve_name(name)` (макрос `define_syscall_table!` в
  `src/libc/mod.rs`, там же `name_of(nr)`); раз в таблицу новую архитектуру не заводить.
- Проверки аргументов: `Rule::check(arg, Cmp::…)` снизу, `Policy::allow_args`/
  `deny_args`/`*_nr_args` сверху; `Cmp`/`ArgCmp` реэкспортированы в `rust`.
